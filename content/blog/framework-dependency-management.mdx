Modern applications combine multiple frameworks and runtime systems.

Typical stack:

- Next.js
- Node.js APIs
- Python services
- PostgreSQL
- Redis
- Docker
- CI/CD pipelines

## Configuration Sprawl

Initial state:

```env
DATABASE_URL=
API_KEY=
PORT=
```

Over time:

```env
REDIS_URL=
JWT_SECRET=
S3_BUCKET=
SMTP_HOST=
PAYMENT_API_KEY=
```

## Configuration as a System

Recommended structure:

```
config/
├── application
├── database
├── authentication
├── storage
└── monitoring
```

## Startup Validation

```typescript
if (!process.env.DATABASE_URL) {
  throw new Error("DATABASE_URL is required");
}
```

Fail fast rather than fail later.

## Environment Consistency

- Same deployment process everywhere
- Same infrastructure definitions
- Minimal environment-specific divergence

## Configuration Debt

Symptoms:

- Duplicate values
- Unused variables
- Manual deployment steps
- Framework-specific hacks

## Conclusion

Configuration is part of system architecture, not deployment detail.
